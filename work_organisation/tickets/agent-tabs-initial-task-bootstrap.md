### Ticket 11: Require and Deliver a Concrete Initial Task When Spawning a Worker

**Status:** DONE

#### Overview

Make `agentctl spawn` accept one concrete initial assignment and store it in the worker's bootstrap inbox before a Codex process is launched. This prevents a visible Codex worker from treating generic launch instructions or its role document as its task, while retaining `agentctl send` as the mechanism for later follow-up work.

#### Implementation Steps

1. **Initial-assignment CLI contract and API validation — `.agent/skills/agent-tabs/agentctl.py`.** Extend the `spawn` parser created in `build_parser()` with a mutually exclusive, required group containing `--task TEXT` and `--task-file PATH`. `--task` is a non-empty UTF-8 text value supplied on the command line; `--task-file` is a path to a UTF-8 regular file whose complete contents become the assignment. Read a task file with `utf-8-sig` so one optional UTF-8 BOM is removed as encoding metadata; then reject content that is empty or whitespace-only. Reject whitespace-only `--task`, a missing/non-file or unreadable `--task-file`, and invalid UTF-8 with a diagnosable `SpawnError` before `backend.open()` is called. Keep `--role PATH` required and unchanged: it remains the role/instructions document, not the assignment. In `_cmd_spawn()`, resolve the selected assignment once and pass its text into `spawn_agent()` as a new explicit `initial_task: str` argument. At the beginning of `spawn_agent()`, before `paths.ensure_agent()`, worktree creation, inbox writes, or `backend.open()`, apply the same nonblank validation to `initial_task`; direct Python callers must receive `SpawnError` for `""` or whitespace-only values. Do not repurpose `--role`, `--model`, or the terminal prompt to carry the assignment.

2. **Bootstrap document schema, immutable payload, and atomic inbox writes — `.agent/skills/agent-tabs/agentctl.py`.** Change `bootstrap_body_for()` (and its `bootstrap_body()` wrapper) to require `initial_task` and render one `0001.md` document with three clearly labeled sections in this order: `## Worker protocol`, `## Role`, and `## Initial assignment`. The protocol section must point to the absolute `.agent/skills/agent-tabs/WORKER.md` path and say it governs inbox checking and `agentctl reply`; the role section must point to the resolved role file and say it defines the worker's standing responsibilities. Make the assignment boundary unambiguous even when task text contains Markdown headings, YAML frontmatter, or look-alike bootstrap text: immediately after `## Initial assignment`, emit the fixed marker `<!-- agent-tabs-initial-assignment utf8-bytes=N -->`, where `N` is the UTF-8 byte length of the exact validated task, then emit exactly those `N` bytes as the assignment payload. The marker and byte count, not headings inside the payload, define the section boundary. Retain the existing inbox path, `agentctl.py reply --status reply|question|blocked` command, and identity/environment warnings. Do not merge role-file content into the bootstrap body.

   Replace the current scan-then-`write_text()` allocation in `write_inbox()` with exclusive atomic creation of the numbered file (for example `Path.open("x", encoding="utf-8")` in a retry loop that advances after `FileExistsError`). The helper must never overwrite a pre-existing message and must return only a fully written, closed file. Preserve zero-padded names and use this helper for bootstrap and `send_message()` so concurrent sends cannot both claim the same inbox number.

3. **Provider launch sequencing and rollback — `.agent/skills/agent-tabs/agentctl.py`.** In `spawn_agent()`, validate and build the complete bootstrap body before calling `backend.open()` for every provider. Create one immutable bootstrap inbox file before launch for **every** provider, regardless of `--no-doorbell`, and retain its exact returned `Path` for the entire spawn attempt. For `WorkerProvider.CODEX`, this must be `paths.inbox(name) / "0001.md"` on a clean spawn and must exist before constructing/opening the Codex argv; pass Codex a concise initial prompt that names both absolute files—the worker protocol and the already-written bootstrap inbox file—and instructs it to read both before exploring or asking questions. That prompt must not duplicate the task text, role text, or say that the role is the task. Preserve the existing Codex liveness check, synthetic `spawned` event, and one `_deliver()` doorbell after the window opens.

   Claude/AGY retain their existing hook handshake and bootstrap acknowledgement flow, but `_bootstrap()` must accept the prewritten bootstrap `Path`; it may retry `_deliver()` exactly once when acknowledgement is missing, and it must never call `write_inbox()` or regenerate the body during a retry. Thus both doorbells point to the same immutable `0001.md`. Define `--no-doorbell` uniformly for Claude, AGY, and Codex: it prewrites the complete bootstrap but suppresses all terminal delivery and acknowledgement/retry behavior. If open, liveness, delivery, or acknowledgement fails, kill the window/worktree through the existing cleanup path and remove the prewritten bootstrap file plus its newly created empty agent directory when it contains no other runtime artifacts; otherwise record the failed bootstrap path in the error event and leave it intact for diagnosis. A retry of the same agent name after a fully cleaned failed spawn must again start at `0001.md`, never `0002.md`.

4. **Follow-up delivery boundary — `.agent/skills/agent-tabs/agentctl.py` and `.agent/skills/agent-tabs/WORKER.md`.** Do not add a second spawn, a task queue, or task parsing to the worker protocol. Keep `send_message()` and the `agentctl send <name> MESSAGE|--file PATH` CLI unchanged as the sole follow-up channel: after a successful bootstrap it writes `0002.md` and later inbox messages using the new atomic inbox helper plus the existing inbox-first and readiness-gated behavior. In `WORKER.md`, state explicitly that the bootstrap's byte-delimited `Initial assignment` payload is the first task, that role and protocol are not assignments, and that later work arrives as new numbered inbox files from `agentctl send`. Keep the existing instruction to check the inbox at the start of every turn and report final/question/blocked outcomes using `agentctl reply`.

5. **Dedicated reviewer example and user documentation — add `.agent/skills/agent-tabs/examples/reviewer-role.md`; edit `.agent/skills/agent-tabs/SKILL.md`.** Add a provider-neutral reviewer role example whose standing responsibility is to inspect the requested diff/change, identify actionable correctness or regression risks, and report findings with file paths and evidence. It must not contain a project name, run-specific assignment, or host-repository vocabulary banned by `test_genericity.py`. In `SKILL.md`, document the required initial-task flags and their exact exclusivity: `agentctl spawn reviewer --role .agent/skills/agent-tabs/examples/reviewer-role.md --task "Review the current diff for regressions" --run demo`, plus a multiline `--task-file brief.md` example. Update the Codex example to include one of these task inputs and explain the ordering: role = standing behavior, bootstrap `Initial assignment` = first concrete request, `agentctl send` = subsequent requests. Do not describe a `--task` value as a lifecycle hook or imply that `agentctl send` is obsolete.

6. **Automated coverage — `.agent/skills/agent-tabs/tests/test_spawn.py`, `.agent/skills/agent-tabs/tests/test_codex_provider.py`, `.agent/skills/agent-tabs/tests/test_send.py`, `.agent/skills/agent-tabs/tests/test_bus.py`, and `.agent/skills/agent-tabs/tests/test_genericity.py`.** In `test_spawn.py`, update all `spawn_agent()` calls and CLI parser fixtures to provide an initial task; assert the parser rejects absent task input, both task inputs together, whitespace-only inline text, and missing, blank, or invalid-UTF-8 task files before a fake backend window is opened. The BOM case must assert successful decoding to the body after the BOM; the blank case includes a BOM plus whitespace and must fail. Add direct `spawn_agent()` tests proving blank `initial_task` fails before `paths.ensure_agent()` or `FakeBackend.open()`. Add Claude and AGY lifecycle coverage proving they prewrite the same task-bearing bootstrap, use their existing hook flow when doorbells are enabled, and suppress both bootstrap delivery and acknowledgement when `--no-doorbell` is set. Assert a Claude bootstrap `0001.md` has distinct protocol, role, and byte-delimited initial-assignment sections, preserves task bytes containing Markdown headings/frontmatter, and contains the task body exactly.

   In `test_codex_provider.py`, make the fake Codex spawn accept an initial task and assert that `0001.md` exists before `FakeBackend.open()` is invoked (use a spy/wrapper), contains the exact task, and that the Codex prompt names its absolute path without embedding the task. Assert `--no-doorbell` still prewrites the complete Codex bootstrap and produces no typed send. Add failed-open, failed-liveness, failed-doorbell, and unacknowledged-bootstrap retry cases that assert cleanup removes the prewritten bootstrap/empty agent directory, the next successful same-name spawn starts at `0001.md`, and an acknowledgement retry produces two pointers to byte-identical `0001.md` rather than a `0002.md`. In `test_send.py`, add a spawned agent with a completed bootstrap and verify `send_message()` creates `0002.md` containing the follow-up body while `0001.md` remains byte-for-byte unchanged. In `test_bus.py`, add a concurrent-writer test (threads or processes suitable for the supported platforms) that calls `write_inbox()` simultaneously, asserts each returned path is unique and consecutively numbered, and verifies every file's full expected body. In `test_genericity.py`, include `examples/reviewer-role.md` in the shipped-file existence and banned-vocabulary checks, or replace the fixed `SHIPPED` tuple with an explicit shipped-path collection that covers it. Fully annotate each new test function to preserve the strict test typing convention.

#### Explicit Constraints & Warnings

- **Initial-task invariant:** A worker launched by `spawn` must always have exactly one concrete initial assignment in its bootstrap inbox. Do not silently substitute the role document, an empty string, a default greeting, or the initial terminal prompt when the caller omits task input.
- **Validation boundary:** CLI validation is not sufficient. `spawn_agent()` itself must reject an empty or whitespace-only task before any filesystem, backend, worktree, or runtime-state side effect.
- **Codex ordering:** The bootstrap file is durable state and must be written before the Codex process is opened. The terminal prompt is only a doorbell/instruction to read it; it is not the authoritative assignment payload.
- **Immutable bootstrap and rollback:** One spawn attempt owns one immutable bootstrap file. A doorbell retry reuses that path only; it must not allocate a new inbox message. Failed prewrite/open/liveness/delivery attempts must clean up their bootstrap artifacts when safe so a clean retry starts at `0001.md`.
- **Uniform no-doorbell behavior:** `--no-doorbell` always means write the durable bootstrap before launch but do not type it, await acknowledgement, or retry it—independent of provider.
- **Protocol/role/task separation:** `WORKER.md` is the transport and reporting protocol, the role file is persistent behavior, and `Initial assignment` is the specific work request. Keep these as separate labeled concepts in code, generated text, examples, and docs.
- **Preserve inbox semantics:** Never overwrite an inbox file. Allocation must use exclusive creation rather than a scan-and-write race; retain zero-padded numbering and inbox-first writes. `agentctl send` remains responsible for all later assignments and must preserve readiness, copy-mode, queue, force, and `--no-enter` behavior.
- **Unambiguous task framing:** Use the specified byte-count marker. Do not rely on Markdown headings, fences, YAML frontmatter, or sentinel text inside arbitrary task content to identify the initial-assignment boundary.
- **Provider boundaries:** Do not add Codex lifecycle hooks, parse Codex terminal output as task acknowledgement, or alter the existing synthetic Codex `spawned` event/liveness semantics. Claude and AGY must retain their current hook handshake.
- **Generic standalone tool:** The shipped Agent Tabs files, including the new example, must remain free of `ticket`, `sprint`, and `cvviewer` as enforced by `.agent/skills/agent-tabs/tests/test_genericity.py`.

#### Acceptance Criteria

- [Automated] The `spawn` parser accepts exactly one of `--task` and `--task-file`; missing, conflicting, blank, missing-file, BOM-only/whitespace task files, and invalid-UTF-8 inputs fail before `FakeBackend.open()`, while a nonblank UTF-8-BOM task file succeeds with the BOM removed.
- [Automated] Direct `spawn_agent()` calls with an empty or whitespace-only `initial_task` fail before any runtime directory, worktree, inbox, or fake backend window is created.
- [Automated] A generated bootstrap `0001.md` has separately labeled Worker protocol, Role, and Initial assignment sections, followed by the exact `agent-tabs-initial-assignment utf8-bytes=N` marker and task bytes; headings or frontmatter in the task cannot alter that framing.
- [Automated] A Codex fake spawn has its complete `0001.md` on disk before the backend receives the Codex open call; its initial prompt references the absolute bootstrap path but does not duplicate the assignment text.
- [Automated] Claude, AGY, and Codex each prewrite `0001.md`; `--no-doorbell` for every provider records no typed bootstrap pointer and skips acknowledgement/retry behavior.
- [Automated] A missing bootstrap acknowledgement yields exactly one retry pointing to the same immutable `0001.md`, never writes `0002.md`, and failed open/liveness/delivery/acknowledgement cleanup lets the next same-name spawn start at `0001.md`.
- [Automated] A normal `agentctl send` after bootstrap creates `0002.md` with the follow-up content without changing `0001.md`.
- [Automated] Concurrent `write_inbox()` callers receive distinct consecutive filenames and each persisted file contains the complete intended body.
- [Automated] The reviewer example exists and is covered by the genericity test's shipped-file and banned-vocabulary assertions.
- [Manual] Spawn a Codex reviewer with `--role .agent/skills/agent-tabs/examples/reviewer-role.md --task "Review the current diff for regressions"`; before interacting with the window, inspect `agents/reviewer/inbox/0001.md` and confirm it contains distinct protocol, role, and concrete-assignment sections. The worker reads those files and returns its findings through `agentctl reply`.
- [Manual] After that reply, run `agentctl send reviewer --file follow-up.md`; confirm the worker receives a new numbered inbox file and handles it as follow-up work without being respawned.
